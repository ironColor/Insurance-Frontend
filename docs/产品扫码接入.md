# 产品扫码与配置接入

本次根据小程序接口文档接入产品数据，产品介绍、方案、投保字段、协议和阅读文件均从服务端读取，不再使用本地示例产品兜底。

接口文档地址：<https://www.zfxbaoxian.com/prod-api/wxmini/v3/api-docs>。

## 扫码与登录

1. PC 端维持现有二维码请求，目标页面为 `pages/index/index`，业务参数包含 `productId`。
2. 微信把产品码参数传入页面的 `scene`。小程序保留原参数，登录后请求 `GET /product/decodeScene/{scene}`，读取 `productId` 和可选的 `shareUser`。
3. 小程序请求 `GET /product/allInfo/{productId}` 加载完整配置。从首页进入也可以直接携带 `productId`。
4. 未登录或会话失效时先保存原入口，登录成功后恢复。普通登录进入首页。
5. 产品页、方案页、投保页、确认页和草稿支付页持续携带产品 ID。确认及支付只读取与页面产品一致的草稿。

App 的数字 `scene` 表示启动来源，与 `query.scene` 中的产品参数分别处理。普通返回前台不会把正在填写的页面重新跳回产品介绍页。连续扫码以最新入口为准，旧异步请求不能覆盖新入口。

## 数据与页面

- `planGroupList`、`planList`、`liabilityList`：映射险种分组、保障方案和保障责任；按可见性、排序和默认选中配置展示。保费用整数分累加。
- `media`：展示介绍 HTML、视频或轮播图片；相对资源路径补充服务站点域名。
- `blockConfigList`、`fieldConfigList`：展示文本、日期、单选、多选、身份证和手机字段，使用服务端默认值、必填及只读设置。选项同时保留显示标签和接口值。
- `forceDocList`：展示提示与阅读内容；每份文件独立处理计时、滚动或两者同时满足的规则。切到后台时暂停页内阅读计时。
- `docList`：协议与产品资料分别展示；文字使用 `RichText`，链接使用 `web-view`，附件使用微信文件预览能力。
- 长整型 ID：请求以文本接收 JSON，在解析前将不安全整数保留为字符串，避免产品、方案和字段 ID 丢失精度。

投保草稿保存该产品的配置快照。已有本地订单缺少快照时提示信息缺失，不套用其他产品配置。

明确的产品禁用、无数据或 404 进入失效提示；网络故障、500 和异常配置保留错误及重试入口。

## 当前边界

- 本次未接入真实订单提交、支付、退款及投保前业务校验接口；支付页保留暂不可用提示。客户端基础校验不能替代服务端核验。
- `pro_field_type` 兼容已有明确语义的字段值，不猜测文档未列出的数字枚举。未知字段类型、条件联动及未定义的动态选项来源会记录 `formIssues` 并暂停投保；介绍和方案仍可浏览。
- `validType`、`validRule`、`busiValidType` 保留在字段元数据中，后续真实订单链路应按服务端契约执行。
- 外部链接或附件要求滚动到底时，小程序无法验证外部阅读器的滚动状态，页面会提示调整为页内文字，不直接标记已读。
- 协议 `web-view`、附件下载及图片视频域名须满足微信后台的业务域名和合法域名配置。打开失败时提供重试或复制链接。

## 验证与联调

本地验证命令：

```sh
npm run typecheck
npm run test:product
npm run build:weapp
```

自动测试覆盖产品字段映射、默认方案、保费精度、文档配置、失效判断、长整数 ID、鉴权头、扫码入口持久化和登录目标恢复。

构建会输出既有的 `TypeError: require(...) is not a function` 警告：现有 `mini.postcss.url` 配置被 Taro Vite 加载器解析到 Node 的内置 `url` 模块。加载器捕获后继续构建，产物正常生成；本次没有调整该历史配置。

仍需在微信开发者工具或真机使用实际登录会话与产品二维码联调：

1. 未登录扫码，授权登录后回到原产品；已登录扫码直接进入产品。
2. 连续扫码两款产品，以及再次扫描同一码，始终展示最后扫码的产品。
3. 从产品介绍进入方案、表单和确认页，核对名称、金额、字段、文件及分享人上下文。
4. 切换产品后回到旧确认页，旧页面不能使用新产品草稿；禁用产品展示失效提示。
5. 核对媒体、协议业务域名及附件预览；测试每份阅读文件的时间与滚动要求。

没有实际微信授权会话时，本地测试与构建不能代替上述真机验收。
